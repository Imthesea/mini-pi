# coding-agent 最小化设计 Spec(Phase 02.5)

> 本文档是 my-mimipi 项目 `packages/coding-agent` 的**最小化**设计。后续会演化为完整 coding-agent spec。
> 上游设计:
> - AI 层:[phase01-ai-core-design.md](./2026-07-29-phase01-ai-core-design.md)
> - Agent 层:[phase02-agent-design.md](./2026-07-30-phase02-agent-design.md)

## 概述

### 目标

搭建一个**能跑通**的 CLI 入口(`mimi` 命令),把 `@mimi/agent` 的 `AgentHarness` 包成可执行的命令行工具。本期只覆盖**单次 prompt** 和**最小 REPL**,不引入 TUI、不引入扩展系统、不引入任何复杂 UI。

### 现状定位

- **暂时性**:这是 MVP,跑通后会用更完整的实现替换
- **演进性**:本 spec 是完整 coding-agent spec 的"种子版本",后续会扩
- **只做 CLI 入口层,不重复造 agent 轮子**:所有 agent 行为(对话、工具、压缩、钩子)都委托给 `@mimi/agent`;本包只负责"输入采集 → 启动 harness → 输出渲染 → 退出"四件事

### 与 pi 的对比

| 维度 | pi `packages/coding-agent` | 本项目 `packages/coding-agent`(本期) |
|------|---------------------------|-------------------------------------|
| CLI 入口 | 完整 TUI(ink)+ 命令系统 + 扩展 | 极简 REPL(readline + console.log) |
| 行数 | ~20,000+ | **~300-500** |
| 扩展系统 | 完整 | 无 |
| MCP | 支持 | 无 |
| OAuth | 完整 | 无(只走环境变量) |
| 模型市场 | 完整 | 无(只走 `--model` flag) |
| Slash 命令 | 30+ | **0**(本期) |
| TUI 库 | ink | 无 |

### 关键决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 包名 | `@mimi/coding-agent` | 与 pi 命名一致,后续扩展时包名稳定 |
| CLI 命令名 | `mimi` | 与项目名 `mimipi` 对齐(短、好打) |
| 入口文件 | `bin/mimi.mjs`(shebang 引导)+ `src/cli.ts`(主逻辑) | 与 Node.js 生态一致,可直接 `npx` 跑 |
| 渲染 | `console.log` 纯文本,无任何 UI 库 | 0 依赖,跨平台,后续替换为 TUI 不影响 agent 调用 |
| REPL | Node.js 内置 `node:readline/promises` | 0 依赖,跨平台 |
| Session 存储 | 复用 `@mimi/agent` 的 `JsonlSessionStorage` | 不重复造轮子 |
| 工具集合 | `read_file` + `write_file` + `bash`(最小三件) | coding-agent 必备;更多工具后续迭代 |
| 环境变量 | `MIMI_MODEL` / `MIMI_API_KEY_*` | 不污染 `OPENAI_*` 命名空间 |
| 退出 | `Ctrl-C` 调 `harness.abort()` 后退出 | 标准行为 |

### 暂不做(显式列表)

为避免范围蔓延,以下项**本期不实现**(后续 spec 接力):

- ❌ TUI / Ink / 任何 UI 库
- ❌ Slash 命令(`/model` `/compact` `/clear` 等)
- ❌ 扩展系统(extensions / skills 加载)
- ❌ OAuth / 交互式登录
- ❌ MCP server / client
- ❌ 多会话切换 / 会话列表 UI
- ❌ Token 计数显示 / 进度条
- ❌ 工具调用的可视化(用文本 diff 即可,不做 box drawing)
- ❌ 持久化设置(`~/.mimi/config.json` 等)
- ❌ 自动压缩触发(跟 agent 层一致,只手动)

## 2. CLI 命令规范

### 2.1 命令形式

```bash
# 单次模式:直接给 prompt,跑完即退
mimi "今天北京天气怎么样"
mimi --model claude-sonnet-4 "解释量子纠缠"

# REPL 模式:无 prompt 参数进入交互
mimi
mimi --resume <sessionId>

# 常用 flag
mimi --model <modelId>            # 覆盖默认 model
mimi --thinking <level>           # off | minimal | low | medium | high
mimi --cwd <path>                # 工作目录
mimi --resume <sessionId>        # 续接 session
mimi --new                        # 强制新 session(忽略 cwd 下的最近 session)
mimi --help
mimi --version
```

### 2.2 退出码

| 码 | 含义 |
|----|------|
| 0 | 正常完成(单次模式响应结束、REPL 调 `exit` / EOF) |
| 1 | 通用错误(API 错误、配置错误) |
| 130 | `Ctrl-C` 终止(SIGINT 标准) |
| 2 | 参数错误(未知 flag、缺值) |

### 2.3 环境变量

| 变量 | 用途 |
|------|------|
| `MIMI_MODEL` | 默认 model(默认 `claude-sonnet-4-20250514`) |
| `MIMI_API_KEY_ANTHROPIC` | Anthropic Key(走 `@mimi/ai` 的 `envApiKey`) |
| `MIMI_API_KEY_OPENAI` | OpenAI Key |
| `MIMI_API_KEY_DEEPSEEK` | DeepSeek Key |
| `MIMI_THINKING` | 默认 thinking level |
| `MIMI_CWD` | 默认 cwd |
| `MIMI_SESSION_DIR` | session 存储目录(默认 `<cwd>/.mimi/sessions`) |

**不污染** `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` 等命名空间,避免与其它工具冲突。

## 3. 主流程

### 3.1 single-shot 模式

```
runCli({ mode: "single-shot", prompt, options }):
1. 加载环境变量(.env,若有)
2. session-init.init({ cwd, options }) → 返回 (session, storage)
3. 构造 AgentHarness:
   model: options.model ?? env.MIMI_MODEL ?? default
   thinkingLevel: options.thinking ?? env.MIMI_THINKING ?? "medium"
   session: session
   env: new NodeExecutionEnv({ cwd })
   tools: [readFileTool, writeFileTool, bashTool]
   systemPrompt: "你是 mimi,一个有帮助的 AI 助手..."
4. 订阅 AgentHarnessEvent → display.formatEvent(event) → console.log
5. await harness.prompt(prompt)
6. harness.close() / storage.close()
7. 退出码 0
```

### 3.2 REPL 模式

```
runCli({ mode: "repl", options }):
1. 加载环境变量
2. session-init.init(...) → session
3. 构造 AgentHarness(同上)
4. 订阅事件 → display.formatEvent → console.log
5. readline 循环:
   while true:
     line = await readline.question("mimi> ")
     if line == "exit" or EOF: break
     if line.trim() == "": continue
     await harness.prompt(line)
6. readline.close()
7. harness.close() / storage.close()
8. 退出码 0
```

**信号处理**:
```ts
process.on("SIGINT", async () => {
  await harness.abort();
  process.exit(130);
});
```

### 3.3 Session 续接

```
session-init.init({ cwd, options }):
  if options.resume:
    路径 = sessionDir + options.resume + ".jsonl"
    尝试打开(若不存在报错)
  else if options.new:
    生成新 id(时间戳)
    路径 = sessionDir + id + ".jsonl"
  else:
    查找 cwd/.mimi/sessions/ 下最近修改的 .jsonl(若有 24h 内,默认续接;否则新建)
    id = (新生成时间戳)
```

## 4. 渲染规范

### 4.1 事件到文本的映射

| AgentHarnessEvent | 输出 |
|-------------------|------|
| `text_delta` | 追加到当前行(无换行) |
| `text_end` | 换行 |
| `thinking_delta` | 灰色追加(以 `🤔 ` 前缀) |
| `thinking_end` | 换行 + 关闭灰色 |
| `toolcall_start` | 蓝色 `🔧 调用工具: <name>(` |
| `toolcall_delta` | 追加 JSON 片段 |
| `toolcall_end` | 蓝色 `)` + 换行 |
| `tool_execution_start` | 黄色 `▶ 执行中...` + 换行 |
| `tool_execution_end` | 绿色 `✓ 完成(123ms)` 或 红色 `✗ 失败: <msg>` + 换行 |
| `turn_end` | 空行(分隔每轮) |
| `error` | 红色 `Error: <msg>` + 换行 |

**颜色方案**:ANSI 16 色,直接用原生转义码;**不引入 chalk**(节省依赖)。`\x1b[36m` = 蓝,`\x1b[33m` = 黄,`\x1b[32m` = 绿,`\x1b[31m` = 红,`\x1b[90m` = 灰,`\x1b[0m` = 重置。

**TTY 检测**:`!process.stdout.isTTY` 时关闭所有颜色(避免污染日志)。

### 4.2 单行刷新

`text_delta` 期间需要单行刷新(不换行),实现:
```ts
process.stdout.write(delta);  // 不带 \n
```

`text_end` 时显式 `process.stdout.write("\n")`。

### 4.3 工具调用展示

工具调用期间**不**实时显示 delta(避免 JSON 半截刷屏),只在 `toolcall_end` 时整体打印:
```
🔧 read_file({"path":"/etc/hostname"})
✓ 完成(12ms) → "my-host\n"
```

## 5. 工具集合(最小三件)

`packages/coding-agent/src/tools/`:

| 工具 | 用途 | 实现 |
|------|------|------|
| `read_file` | 读文件 | `fs/promises.readFile` + path 安全检查(不能逃出 cwd) |
| `write_file` | 写文件 | `fs/promises.writeFile` + 路径安全检查 |
| `bash` | shell 命令 | `child_process.exec` + 超时(默认 30s)+ 输出截断(默认 50KB)+ cwd 限制 |

**路径安全**:所有路径工具必须**拒绝逃出 cwd** 的访问,`/etc/hostname` 这样的绝对路径直接拒绝(返回错误,不抛异常)。

```ts
const resolved = path.resolve(cwd, inputPath);
if (!resolved.startsWith(cwd + path.sep) && resolved !== cwd) {
  return { ok: false, error: { code: "permission_denied", message: "Path escapes cwd" } };
}
```

**实现位置**:`packages/coding-agent/src/tools/`(本地实现,不放 agent 层)。agent 层只提供 `AgentTool` 接口,具体工具由本包绑定。

## 6. 错误处理

| 场景 | 行为 |
|------|------|
| API Key 缺失 | `Error: MIMI_API_KEY_ANTHROPIC not set. See .env.example.` + 退出码 1 |
| 模型未知 | `Error: Unknown model "xxx". Available: claude-sonnet-4, gpt-5.5, deepseek-v4-flash` + 退出码 2 |
| Session 文件损坏 | 警告并新建(不报错退出) |
| Tool 执行超时 | 工具返回 `isError: true`,harness 自然让模型看到错误 |
| Tool 路径越界 | 工具返回 `isError: true` |
| LLM 流中断(网络) | agent 层重试;重试失败后退出码 1 |
| Ctrl-C | `harness.abort()` + 退出码 130 |

**不抛异常给用户** —— 所有错误走 `console.error` + 退出码。

## 7. 与 agent 层的契约

| 来源 | 用法 |
|------|------|
| `AgentHarness` | 主类,所有对话/工具/会话都通过它 |
| `JsonlSessionStorage` | session 持久化 |
| `NodeExecutionEnv` | 文件/命令执行(供 tools/ 使用) |
| `AgentHarnessEvent` | 订阅事件,渲染输出 |

| `abort` | 处理 SIGINT |

**本包不调用** agent 层的:compaction、hooks、skills、prompt-templates(本期)。这些留给后续 spec 接力。

## 9. 风险与待办

| 风险 | 应对 |
|------|------|
| `bin/mimi.mjs` 路径在不同安装方式下可能失效 | 文档明确 `pnpm install --global` 或 `npx mimi` 两种用法 |
| Readline 在非 TTY 环境(`echo "hi" \| mimi`)行为不同 | 检测 `!process.stdin.isTTY` 走 single-shot 模式 |
| ANSI 颜色在 Windows cmd.exe 下可能乱码 | 检测 `process.platform === "win32"` 时默认关闭颜色 |
| Session 文件并发(同一 session 多窗口) | 本期不处理(明示为限制,后续 spec) |
| Tool 路径安全绕过(symlink) | 路径检查用 `fs.realpath` 二次校验(本期实现) |
| 大量输出时单行刷新闪烁 | 本期可接受;后续 TUI 化解决 |
