每次写完代码（无论测试还是实现），必须对比原 pi 项目 `F:\allProject\githubProject\pi` 中的对应文件，检查代码方向是否跑偏。

**核心原则：**
- 尽量一比一还原 pi 的代码结构、命名、文件组织
- V1 是最小化实现，暂时无法一比一还原的可以妥协
- 关键是对齐 pi 的**架构思路和调用关系**
- 暂时无法对齐的，标注差异和原因即可

**检查清单：**
- 文件路径是否与 pi 一致？
- 类名、方法名是否与 pi 一致？
- 核心调用关系（A → B → C）是否与 pi 一致？
- 差异项记录下来，标注"已对齐"/"妥协（原因：V1 缺少 XX 子系统）"

**Why:** pi 是唯一参考标准，比对是为了防止代码方向跑偏，不是为了复制。

**How to apply:** 写完代码后，打开 pi 对应文件，对比结构和调用关系，记录差异。
